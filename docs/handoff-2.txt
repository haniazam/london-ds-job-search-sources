London DS Job Board — Handoff

A briefing for recreating and maintaining the Job Board outside Claude Code, in a plain Claude chat or Project. Written 10–11 October 2026.

Who this is for
- Hani Azam, running a London Data Science job search, who wants the board and its Sheet recreated and maintained without the repo, the skill or the shell — or automated with them.

What exists
- Board: https://claude.ai/artifact/UcMLHVF7Zfh5y67a77Skp3 (v11) — every verified-live London DS role, Target List format: rule-based 0–10 score, tiers, fit and stability, pipeline status per role, next action, cards or table, tagged set-aside list. Lato, light and dark.
- Sheet (source of truth): https://docs.google.com/spreadsheets/d/1tr7h-veYlLIQtewkBw8OY-Zz_7l-4cNNNjs8AO7BoSg — 109 roles at 52 employers as of 10 Oct 2026, plus 27 no-role or unverified rows.
- Repo: haniazam/london-ds-job-search-sources, branch claude/optimistic-ramanujan-80by3 (main at f2acc05). Skill: .claude/skills/refresh-london-ds — discover.py, refresh_roles.py, pay_enrich.py, role_taxonomy.py, boards.json, pay_overrides.json, SKILL.md.

The rules
- Scope: Standard DS titles = the core role is Data Scientist, or Data Science Manager / Lead / Head / Director. Specialism words (Economist, Machine Learning, Research, Applied) never exclude; only a different core discipline does (Research Scientist, ML Engineer, Applied Scientist, Quant, Analyst, Engineer, Economist-as-the-job). Tested in role_taxonomy.py.
- Location: London or London-eligible (Remote-UK, or a multi-location post listing London). Regular and Senior both included. Intern, graduate, apprentice, placement excluded. Agency and recruiter posts excluded.
- Every row is a unique live posting verified on the employer's own board or API. Closed and unverified roles move to the set-aside section with a reason; nothing is deleted.
- Sheet columns, in order: Company, Role, Role Type, Level, Approx London TC, Location, Apply URL, Status, Notes. Active rows first grouped by company, then a divider row, then the set-aside rows.
- Comp is three-tier and always labelled: posted (employer's range) › sourced (Levels.fyi / Glassdoor) › market est. (ITJobsWatch London median for the title, −15% to +25%). Never present a market band as company data.
- Score (printed on the board) = fit (Strong 4, Stretch 2, Level gap 1) + comp (ceiling ≥ £150k: 4 if posted or sourced, 3 if estimated; £120k–£149k: 2; £100k–£119k: 1) + London-proper 1 + verified 1. Tiers: 7–10 Apply now, 5–6 Consider, ≤ 4 Monitor.
- Fits the brief = Senior or above with a product / experimentation / causal / measurement / growth title, per the brief: Senior → Staff, Product DS, £150k+ total comp, exclude Meta, sponsorship to confirm.
- Pipeline statuses (yours, saved in the browser): To apply (default for score ≥ 7), Applied, Interviewing, Offer, Rejected, Monitoring (default otherwise). Set-aside tags: Monitor, Closed, Unverified, Out of scope, Profile mismatch, Caution, Below floor.
- Liveness: a Greenhouse / Ashby / Lever post is live only if its board API still returns it. A dead LinkedIn or Google post returns HTTP 200 with a generic title ("N,000+ jobs", "Jobs search"), so judge by the title naming the company and role, never the status code. Google posts can close within a day.

How discovery works (every refresh starts from all employers, not a target list)
- discover.py runs before refresh_roles.py and pulls London DS postings from cross-employer sources, then classifies each title, drops agencies, and resolves every lead to the employer's own posting.
- No key needed: LinkedIn guest job search (newest first; covers every employer that posts on LinkedIn), Workable's cross-employer feed (the employer's own live state), Built In London (lead source).
- Free keys, optional, set in the environment: Adzuna (ADZUNA_APP_ID, ADZUNA_APP_KEY) and Reed (REED_API_KEY) — UK-wide, including non-tech employers. These are what make coverage genuinely exhaustive.
- Resolution: a lead on a supported ATS (Greenhouse, Ashby, Lever, Workable, SmartRecruiters, Pinpoint, Workday, Teamtailor) yields a board token appended to boards.json automatically — the registry grows itself and that employer is enumerated by API on every later refresh. An employer-site post is verified by GET + title and included via discovered_posts.json. Unresolved leads are kept, labelled, in discovered_leads.json.
- Modes: --bootstrap covers the past month with deeper paging (first run, or after a gap); the default covers the past week, newest first, which is enough daily.
- Limits: LinkedIn rate-limits anonymous search (429); the script paces and backs off, and a throttled run is incomplete, not empty. Indeed and Welcome to the Jungle block scripts. The manual site-scoped search harvest in SKILL.md remains the weekly deep sweep.
- Status: the first bootstrap run was started on 11 Oct 2026 and is being validated; fixes it surfaces follow in the repo.

How to build the Sheet from scratch
- With the repo (Claude Code, or any shell with Python 3 and network): clone the repo; run python3 .claude/skills/refresh-london-ds/discover.py --bootstrap; then python3 .claude/skills/refresh-london-ds/refresh_roles.py (writes /tmp/ldn_ds_active.csv with a Role Type column; Playwright optional for the JS sites); then python3 .claude/skills/refresh-london-ds/pay_enrich.py /tmp/ldn_ds_active.csv (writes /tmp/ldn_ds_active_pay.csv with the comp column).
- Filter to Role Type = Standard DS, sort by company, and write the rows into the Sheet in place with the Sheets tool (A2:I plus the row count, nine columns), then a blank row, the divider row, and the set-aside rows. Scripts cannot write to Drive or Sheets; that step is always the assistant's.
- If the Sheet must be recreated: upload the CSV as text/csv into Drive folder 1jkaK-hFTZf8U6iRJ9clV6Q-LSxJ3eaYI titled London DS — Combined Active Job Posts vN (date).
- Without the repo (a plain chat): paste this briefing and the Sheet link and ask Claude to query the same sources and APIs — LinkedIn guest search, Workable feed, Built In London, Adzuna and Reed if keys are available, plus the ATS APIs for the employers below — apply the rules, verify each posting, enrich comp, and write the Sheet.

How to refresh daily
- Order: discover.py → refresh_roles.py → pay_enrich.py → filter Standard DS → diff against yesterday's Sheet by URL (new, closed, comp changed, still unverified) → write the Sheet in place → republish the board from the same file path (link unchanged) → report the diff.
- Guardrails: never delete, always label; a 429 or gated API makes a row unverified, not closed; comp is never blank or unlabelled — if pay_enrich.py fails, stop rather than publish; pipeline statuses are the user's and are keyed by URL, so a republish preserves them.
- Persist a snapshot of each run (e.g. data/snapshots/YYYY-MM-DD.csv in the repo) so every diff is reproducible and history is free.
- Automation: in Claude Code on the web, create a Routine on the repo environment, fresh session per run, Google Drive and Google Sheets connectors attached, cron 45 7 * * 1-5 in Europe/London. Prompt: "Run the refresh-london-ds skill end to end: discover.py, refresh_roles.py, pay_enrich.py, filter Role Type = Standard DS. Read the current Sheet and diff by URL. Update the Sheet in place with the Sheets tool — never create a new file. Regenerate the board from the Sheet rows and republish it to https://claude.ai/artifact/UcMLHVF7Zfh5y67a77Skp3 from the same file path. Keep closed and unverified roles in the set-aside section with a reason; never delete rows. Reply with the diff only; if nothing changed, say so in one line."
- Weekly: a second Routine runs the manual deep sweep from SKILL.md (site-scoped searches over each ATS host, the radar diff at https://hani-job-search-radar.azamhani95.chatgpt.site/api/state) and commits new tokens to boards.json.
- Reply filter worth encoding: report loudly when posted or sourced pay ≥ £150k appears, a brief-fit role appears, or a shortlisted role closes; one line otherwise.
- A GitHub Actions cron can run the scripts and commit the CSV but cannot update the Sheet or the board, so the Routine is the complete option. Without automation, a plain chat can do the daily pass by hand with this briefing and the Sheet link.
