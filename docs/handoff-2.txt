Who this is for:
Hani Azam, running a London Data Science job search, who wants to recreate and maintain the London DS Job Board outside Claude Code, in a plain Claude chat or Project, without the repo, the skill or the shell.

What we covered:
The board is a single HTML artifact at https://claude.ai/artifact/UcMLHVF7Zfh5y67a77Skp3 (version 11) that renders every verified-live London Data Science role from the Google Sheet with id 1tr7h-veYlLIQtewkBw8OY-Zz_7l-4cNNNjs8AO7BoSg, titled London DS Combined Active Job Posts. The Sheet is the source of truth; the board is a view of it. Over this session the board went from 15 roles to 109 at 52 employers, gained three-tier comp labels, a Fits the brief flag, and finally the Target List's structure: a rule-based 0 to 10 score, tiers, fit and stability chips, a per-role pipeline status, a next action, expandable detail, cards or table views, and a tagged set-aside list. It is set in Lato with a cobalt accent and works in light and dark.

What was confirmed:
Scope: Standard DS titles only, meaning the core role is Data Scientist or Data Science Manager, Lead, Head or Director; specialism words like Economist, Machine Learning, Research or Applied never exclude. London or London-eligible (Remote-UK, or a multi-location post listing London). Regular and Senior levels both included. Intern, graduate, apprentice and placement excluded. Recruiter and agency posts excluded. Every row is a unique live posting verified on the employer's own board.
Sheet columns, in order: Company, Role, Role Type, Level, Approx London TC, Location, Apply URL, Status, Notes. Active rows first, grouped by company, then a divider row, then companies with no active role or unverified leads with a reason in Notes.
Comp is three-tier and always labelled: posted (the employer's range), sourced (Levels.fyi or Glassdoor), or market est. (ITJobsWatch London median for the title, minus 15 percent to plus 25 percent). Never present a market band as company data.
Score formula, printed on the page: fit (Strong 4, Stretch 2, Level gap 1) plus comp (ceiling at or above 150k: 4 if posted or sourced, 3 if estimated; 120k to 149k: 2; 100k to 119k: 1) plus London-proper 1 plus verified 1. Tiers: 7 to 10 Apply now, 5 to 6 Consider, 4 or less Monitor. Fits the brief means Senior or above with a product, experimentation, causal, measurement or growth title, per the user's brief (Senior to Staff, Product DS, 150k plus total comp, exclude Meta, sponsorship to confirm).
Pipeline statuses: To apply (default for score 7 plus), Applied, Interviewing, Offer, Rejected, Monitoring (default otherwise). Saved only in the viewer's browser. Set-aside tags: Monitor, Closed, Unverified, Out of scope, Profile mismatch, Caution, Below floor.
Liveness rule: a dead LinkedIn or Google post returns HTTP 200 with a generic page title, so liveness is judged by the title naming the company and role, never by the status code.

How to build the Sheet from scratch:
With the repo (Claude Code or any shell with Python 3 and network): clone haniazam/london-ds-job-search-sources, then run python3 .claude/skills/refresh-london-ds/refresh_roles.py. It reads boards.json (the registry: greenhouse 73, ashby 33, lever 11, workable 10, smartrecruiters 8, pinpoint 6, recruitee 1, workday 10 boards) and enumerates every board through its public API (Greenhouse boards-api.greenhouse.io/v1/boards/TOKEN/jobs, Ashby api.ashbyhq.com/posting-api/job-board/ORG, Lever api.lever.co/v0/postings/ORG, Workable apply.workable.com/api/v1/widget/accounts/ACCOUNT, SmartRecruiters api.smartrecruiters.com/v1/companies/ID/postings, Pinpoint ACCOUNT.pinpointhq.com/postings.json, Workday POST .../wday/cxs/TENANT/SITE/jobs, Amazon amazon.jobs/en/search.json, Google careers results HTML), keeps London or London-eligible Data-Science-family titles, drops intern, graduate, apprentice, placement and recruiter boards, and writes /tmp/ldn_ds_active.csv with a Role Type column. The JS-rendered sites (Spotify, TikTok, Point72, Bloomberg, Microsoft, G-Research) need Playwright: pip install playwright; the pre-installed Chromium is used when present. Then run python3 .claude/skills/refresh-london-ds/pay_enrich.py /tmp/ldn_ds_active.csv, which writes /tmp/ldn_ds_active_pay.csv with the three-tier Approx London TC column. Filter to Role Type equals Standard DS, sort by company, and write the rows into the Sheet in place with the Sheets tool (range A2:I plus the row count, nine columns), followed by a blank row, the divider row, and the no-role and unverified rows. If the Sheet must be recreated, upload the CSV as text/csv into Drive folder 1jkaK-hFTZf8U6iRJ9clV6Q-LSxJ3eaYI with the title London DS Combined Active Job Posts vN (date). Scripts cannot upload to Drive; that step is always the assistant's.

How to refresh daily:
A daily refresh re-verifies every listed posting and catches new ones; discovery of new employers is weekly. Steps: run refresh_roles.py then pay_enrich.py as above; compare the new Standard DS rows to yesterday's Sheet by URL to produce the diff (new roles, closed roles, comp changed, still unverified); write the Sheet in place; republish the board from the same file path so its link does not change; record the diff in the Changes view or in a short note. Liveness rules that matter daily: a Greenhouse, Ashby or Lever post is live only if its board API still returns it; a dead LinkedIn or Google post returns HTTP 200 with a generic title such as N,000 plus jobs or Jobs search, so judge by the title naming the company and role; Google posts can close within a day; Workable rate-limits with 429, so pace calls and treat a 429 as unverified rather than closed; SmartRecruiters gates its API per company, so verify those by the posting page title. Keep closed and unverified roles in the set-aside section with the reason rather than deleting them.
To automate it: in Claude Code on the web, create a Routine (scheduled task) on the repo environment with a cron such as 45 7 * * * in Europe/London that starts a fresh session each day with the prompt: run the refresh-london-ds skill, update the Sheet in place, republish the board, and reply with the diff; give the Routine the Google Drive and Google Sheets connectors. A GitHub Actions cron can run the two scripts and commit the CSV, but it cannot update the Sheet or the board, so the Routine is the complete option. Without automation, a plain chat can do the daily pass by hand: paste this briefing and the Sheet link and ask for a re-verification of every row plus a check of each registry board for new London DS posts.
